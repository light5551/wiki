## Датасет 

На начало 2026 года имеется 2к часов намайненных с ютуба. Данные для навигации состоят из эпизодов движения робота с дополнительной информации в виде траекторий, параметров камер, (optional) камеру глубины
### Источник данных
В качестве основного источника данных предполагается сырые видеоизображения без дополнительных метаданных

#### Внутренние источники
* Данные записанные с проходки наших роботов по ЦР
* Сотрудники/стажеры в сенсор костюмах. Ограничены количеством костюмов + дата лейблерами. Качество данных HighQuality.
* Данные собранные через сенсорбокс. Качество данных HighQuality+,  много не собрать, но могут быть полезные на последней стадия обучения. Необходимые для GaussianSplating для post-train обучения
* Данные из симулятора
  * IsaacSim для сенсоров
  * Mujoco -- для динамической системы. Только одно применение, так как пока физика лучше, временно. Со временем помрет
* Сторонние проекты из команды Solution
  * Dog(?)
  * Worker(?)
#### Внутренние источники (В рамках сбера)
* Датасеты собранные с Navio
* Данные из Сколтеха (200к часов -- стерео)
* Сбер.Охрана(?возможно ли)
#### Внешние данные
* Использование данных с ютуба
* Открытые ресерчерские датасеты для навигации для PointNav, ImageNav и др

### Разметка данных 

Поскольку в наших данных изначально нет никаких метаданных,  есть необходимость вычислить параметры камеры для получения позы камеры. 

### Проблема качества данных

Гарантии "физичности" полученных поз нет, поэтому необходим процесс фильтрации полученных траекторий из поз. Фильтры:
1. Сегментация людей. Проверка траектории на коллизию с людьми
2. Траектории которые имеют больше определенного трешхолда значения от предыдущего по расстоянию
3. кривизна 


### Итоговый ETL-пайплайн

Общая схема выглядит следующим образом:
1. Eжедневно берется батч сырых данных видеоизображений из S3
2. Расчет признаков -- запускается VGGT пайплайн для создания параметров камеры -> поз -> траекторий
3. (Optioanl) VLM аннотирование видео с сохранением тегов что изображено на каждом фрейме
4. Фильтрация на валидность траектории по форме траектории, по сегментации 
5. Преобразование данных в parquet(webdataset) и отправка на NFS

## Cхема валидации

### Валидация обученной модели

1. Проверка интерактивная в симуляторе на сценах, которые описывают различные навигационные паттерны, симулируют различное окружение(освещение, тени и др)
2. Проверка на записанных проходках в ЦР
3. Benchmark
4. NavDP benchmarks
5. Benchmarks из ЦР Кутузы, новой площадки
6. Валидация всегда происходит на модуле которые идентично запускается на роботе, т.е. через ROS ноду
7. Сценарий/часть датасета должна быть только в одной выборке, или в train, или в test, чтобы не допустить утечки данных
